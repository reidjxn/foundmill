

## 2026-11-14 — Every api list and map is bounded before zod reads it (GHSA-mrhx-c7xc-m3w5, follow-up to #139)

zod 4.6.7 stops an array, set or map at a length check placed first in its chain, but still reads every element of an array without `.max()` and every key of a record, building an issue per failing one: a signed-in member's 2 MB body could make the api build hundreds of thousands of issues (P3: needs an account).
- **Helper.** `boundedRecord(max, record, message?)` and `fewKeys(max)` in `packages/shared/src/bounded-record.ts`: a plain object (prototype `Object.prototype`) with at most `max` keys, counted with `for…in` before zod reads a key, then the record as before; anything else is one short issue.
- **Limits.** `INPUT_LIMITS` in `packages/config/src/limits.ts` (ids, approvers, tool grants, instruction lines, aliases, identifiers, glossary terms, register imports, widgets, linked ids, forecast months, free-form JSON keys); enum lists are bounded by their enum's length; playbook `where` and step params by `PLAYBOOK_WHERE_MAX_KEYS` / `PLAYBOOK_PARAMS_MAX_KEYS` beside the schema.
- **Sites.** Every array and record a procedure input reaches: in `apps/api/src/routers` (agent, business, crm, department, dev, integrations, legal, page-quiz, product, team), and the schemas they take from `packages/db/src/repos` (businesses, campaigns, capTable, departments, entities, finance, founders, inbox, journeys, legal, memberships, preferences, product, screens, tasks), `packages/agents` (`AgentInstructions`) and `packages/shared` (`PlaybookTrigger.where`, `PlaybookStep.action.params`, read by `team.playbooks.*`).
- **Tests.** `apps/api/src/__tests__/input-limits.test.ts`: a walk over every procedure's input schema finds no array, set or map without a cap first and no record without its key guard (a new unbounded input fails it); for each of 64 bounded fields through the caller, one past the limit and 100,000 junk elements or keys are a BAD_REQUEST with at most 3 issues and a message under 2,000 characters, the limit itself passes the procedure's input parsers, a small valid input passes input validation; five representative calls succeed end to end; playbook flows. `packages/shared/src/bounded-record.test.ts` (limit, plain objects only, `__proto__`, a Map, 200,000 keys as one issue).
- **Not changed.** `apps/ingest/src/simulate.ts` (behind a service token). Schemas that parse model output or stored rows and never a request (`OptionAction.params`, `PostDraft.variants`, the jurisdiction cards in `legal.ts`, the idea verdict in `idea.ts`).
