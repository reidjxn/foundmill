## fix:db-pglite — @foundmill/db (packages/db)

PGlite is now a first-class driver in packages/db. New module /home/user/foundmill/packages/db/src/pglite.ts owns everything PGlite-specific in one place: URL parsing (`pglite:<dir>` file-backed, `pglite::memory:`; relative dirs resolve against the workspace root so `pnpm --filter` cwd differences cannot split the data), the bootstrap SQL (anon/authenticated/service_role roles, stub `auth` schema with `auth.uid()`/`auth.role()` reading `request.jwt.claims`, pg_trgm + pgvector), `bootPglite`, and `LazyPgliteClient`, which lets `createDb` stay synchronous (every service calls it at module scope) by queuing the first query/transaction behind "WASM ready + bootstrap applied"; it also answers `end({timeout})` so apps/orchestrator's `db.$client.end` works on either driver. `src/client.ts` `createDb(url)` dispatches on the URL (overload narrows a `pglite:` literal to `PgliteDb`; otherwise returns `AnyDb = ServiceDb | PgliteDb`, both assignable to the unchanged `Db`), `createServiceDb` returns `AnyDb`, `withRls` works unchanged on PGlite, and `closeDb(db: Db)` closes whichever driver is underneath. New `src/migrator.ts` exports `migrateDb(db)` / `appliedMigrationCount(db)` which run packages/db/migrations in journal order through drizzle's own `drizzle.__drizzle_migrations` bookkeeping on either driver, so a directory seeded by `pnpm db:seed` and later opened by apps/api's boot migrator sees nothing left to apply (the api's existing postgres-js-migrator + pg_advisory_lock path is covered by a test on PGlite and works as-is). `src/testing/pglite.ts` and `src/seed/pglite-target.ts` no longer carry copies of the bootstrap SQL: the harness boots through `bootPglite`, and `openLocalPglite(dir)` is literally `createDb("pglite:<dir>")` + `migrateDb` (its private `_foundmill_local_migrations` table is gone). `src/seed.ts` picks the PGlite directory from `DATABASE_URL=pglite:<dir>`, `SEED_TARGET=pglite`/`SEED_PGLITE_DIR`, or the default `./.pglite/dev` (`resolvePgliteSeedDir`), and logs the absolute `DATABASE_URL=pglite:<dir>` to paste into the services' env; `src/migrate.ts` (`pnpm db:migrate`) uses `migrateDb` for both URL forms. A two-process probe showed PGlite silently diverging when two processes open one directory (each applied all 12 migrations), so `bootPglite` takes an advisory lock `<dir>/foundmill.lock` (pid + time); a second opener fails with "already open in process N" and a stale lock (dead pid) is taken over. Verified end to end: `DATABASE_URL=pglite:<dir> pnpm db:seed` (12 migrations + seed), `pnpm db:migrate` on the same URL (0 applied), `SEED_TARGET=pglite SEED_PGLITE_DIR=<same>` re-seed (0 migrations, businesses rebuilt), and a relative URL run from apps/api cwd landing in <root>/.pglite. Docs: DECISIONS.md "PGlite as the local database driver", PROGRESS.md row + build-log line, NEEDED_DEPS.md (pglite + pgvector should move to runtime dependencies; optional pglite-socket for a multi-process local stack). The entity-linker relative import in the seed test was left as instructed. All apps that consume the db client (composer, gateway, ingest, stream, collab, orchestrator, social) still typecheck; apps/api's typecheck fails only in another agent's in-progress router files (see openIssues).
